# Go Mode

Standalone Go Mode contracts, MCP and OAuth transports, generated SDKs, browser
integration, and Android shell. Host repositories own product APIs, auth policy,
content, and MCP tool/resource semantics. Keep the root Go package free of heavy
voice gateway dependencies and host imports.

Read the narrower guides before editing `mcp/`, `oauth/`, `android/gomode/`,
`android/halo/`, or `voicegateway/voicertc/`. The MCP guide requires checking the
current protocol draft before protocol changes.

User and integration guides live at https://docs.gomode.dev, whose source is
the sibling `docs.gomode.dev` repository; update it when user-visible behavior
or a host contract changes. Document contracts and internals in comments beside
the owning source. `docs/` holds only implementation plans, unbuilt designs,
and research notes.

Use `make fix`, `make verify`, and `make test` after changes.
`make fix` also regenerates SDKs after DTO or route changes. `make android-test` builds
the Android app and SDKs, compiles instrumented tests, and runs build-dependent
lint, unit tests, and coverage.

`verify` runs static checks, including Android Detekt and ktlint for changed
Android, SDK, or build inputs. `test` runs tests and includes Android builds,
build-dependent Android lint, unit tests, and coverage for those inputs. Pre-push
runs only `make verify`. `make android-lint` and `make android-test` run their
Android checks unconditionally. CI runs `make android-lint android-test`.

Run `go test -tags=integration -run '^TestIntegration' ./...` for Go tests
that invoke toolchains, generate RSA keys, or exercise paced WebRTC media.
The Chromium cases use `CHROME_BIN` or `chromium` on PATH.

Automatic Android checks in `fix`, `verify`, and `test` compare against upstream
locally or `ANDROID_CHECK_BASE` when supplied. Without a usable base they run
unconditionally. The platform-neutral CI job sets `ANDROID_CHECKS=false` because
the dedicated Android job runs the explicit checks.
Gradle runs with `--quiet`. `ANDROID_VERBOSE=true` makes Gradle in `fix`,
`verify`, `test`, `build`, and the `android-*` targets log each task and its
outcome; set it for logs kept as gate evidence.

Mandatory: Run `make git-hooks` to install git hooks before making any change.

Android changes MUST run applicable instrumented tests on an emulator, in addition
to `make android-lint android-test`. If no emulator or AVD is present, provision
and start one with `make android-start-emulator`, then run the tests. An absent emulator, system
image, or connected device is NOT a reason to skip Android tests. Use
`make android-e2e` for all model-free app, gateway, and independent Telecom tests.
Use `uv run --locked python scripts/android_e2e.py --class <Class[#method]>` for focused app coverage,
adding `--module telecom` for the independent fixture APK. Real model inference
and large transfers require explicit acceptance-test selection and opt-in arguments.

The TypeScript package `@gomodedev/gomode` exports source for Solid/Vite hosts.
Keep `web/src` host neutral and configure its MCP endpoint in each host.

## Versioned Contracts

Every wire API and serialized format has a version. Wire APIs are HTTP routes,
WebSocket and data-channel messages, native bridge calls, MCP extensions,
tokens, and SDK types. Serialized formats are the files, logs, caches, Android
storage, and browser storage that Go Mode writes. A route path, file path,
subprotocol, or `version` field holds the version; a format without one is
version 1. MCP and OAuth carry their specification's version; version only Go
Mode extensions to them. Go symbols that hosts import follow module tags.

A breaking change ships as version N+1 beside version N:

- Breaking: remove or rename a field, route, or enum value; change a type,
  unit, or meaning; make an optional field required; reject input that
  version N accepts. Adding an optional field or a route, or changing a
  default, is not breaking.
- Copy the vN package to vN+1 and change the copy. `voicegateway/api/v2`
  beside `api/v1`, with `voicegateway/compat.go` and
  `voicegateway/voicertc/compat.go`, is the reference.
- Use the vN types directly. Do not declare type, constant, or variable
  aliases or forwarding wrappers for them; saving churn does not justify an
  alias.
- Move clients and writers to vN+1. Serve and read vN through an adapter over
  the current implementation.
- Mark each vN declaration and adapter with
  `TODO(YYYY-MM-DD): delete vN once this date has passed and two release tags contain vN+1.`
  The date is the commit date plus 7 days. Count tags with
  `git fetch --tags origin && git tag --contains <commit that added vN+1>`.
- When both conditions hold, delete vN with its adapter, tests, and
  generated SDK.

## Python tools

Run Python tools and repository scripts with `uv run --locked`.
Run `uv lock` after changing Python dependencies.
